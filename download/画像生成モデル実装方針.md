# ブラウザ内画像生成（T2I / I2I）実装方針ドラフト

対象: `llm-in-the-website`（Wllama チャットアプリ）への Stable Diffusion 系画像生成の統合
ステータス: 設計ドラフト（実装前・方針レベル。数値は要検証の箇所あり）

---

## 1. 目的とスコープ

- チャット用 LLM に加え、**テキスト → 画像（T2I）** と **画像 → 画像（I2I / img2img）** をブラウザ内だけで実行できるようにする。
- 配信形態は現行と同じ **純静的ホスティング**（Cloudflare Pages）を維持する。サーバサイド推論は使わない（オプションのフォールバックを除く）。
- 初期スコープは「動く最小構成」。ControlNet / Inpainting は後続フェーズ。

## 2. 現行アーキテクチャとの関係

| 項目 | 現行（LLM） | 画像生成（本方針） |
| --- | --- | --- |
| ランタイム | Wllama (llama.cpp WASM / WebGPU) | ONNX Runtime Web または stable-diffusion.cpp WASM |
| モデル形式 | GGUF | ONNX（fp16/int8）または GGUF |
| 実行場所 | Web Worker 内 | **専用の別 Worker**（LLM と分離） |
| キャッシュ | なし（メモリ上のみ・計画書 M-2） | **あり（Cache API / OPFS）** を推奨 |
| 設定の一元管理 | `appConfig.ts` の APP_CONFIG | 同じ APP_CONFIG に `SD_*` 変数を追加 |

重要制約: **LLM と画像モデルを同時にメモリへ載せない**。
wasm32 の 4GB アドレス空間とデバイスメモリ（iPad は特に厳しい）の両方から、
片方をロードする前にもう片方を `exit()` で完全解放する排他制御をエンジン層に実装する。

## 3. 技術選定候補の比較

| 候補 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| **A. transformers.js + ONNX Runtime Web（WebGPU EP）** | `text-to-image` / `img2img` パイプライン（sd-turbo / sdxl-turbo / SD1.5 の ONNX 版） | ブラウザでの実績が最多。WebGPU で実用速度。実装コスト最小。静的配信で完結 | モデルが ONNX 形式（現行 GGUF ワークフローと別物）。fp16 は端末依存の挙動あり（要検証） |
| **B. stable-diffusion.cpp の WASM ビルド** | llama.cpp 系の SD 実装を wllama 同様に wasm 化して自己ホスト | 現行と思想が統一（GGUF / 量子化 / LoRA）。メモリ効率の可能性 | WASM + WebGPU の組合せは未成熟。ビルド・保守コストが大。実用速度は未検証 |
| **C. サーバ API（任意フォールバック）** | 外部 API に委託 | 低スペック端末でも動く | 静的ホスティングの前提が崩れる・コスト・プライバシー |

**推奨: 段階採用。** 第一段階は A で早期に動くものを作り、第二段階で B を PoC 検証して
GGUF 統一の価値（LoRA 流用・量子化・既存 UI の再利用）が見積もれたら移行判断する。

## 4. アーキテクチャ設計（案）

```
src/
  config/appConfig.ts        … SD_DEFAULT_MODEL_URL / SD_SIZE / SD_STEPS / SD_CACHE_ENABLED などを追加
  lib/imageEngineStore.ts    … 画像生成エンジンの Zustand ストア（排他制御・進捗・履歴）
  lib/imageGeneration.worker … 生成 Worker（transformers.js / ORT をここで動かす）
  components/panels/ …       … 左パネルに「画像モデル」セクション（LoRA セクションの構造を流用）
  components/gallery/ …      … ギャラリー（IndexedDB に生成画像 + メタデータを保存）
```

- **排他制御**: `chatStore` / `imageEngineStore` の双方に「生成中はもう一方のロード/生成を禁止」
  ガードを入れる。StatusBar に現在アクティブなエンジン（LLM / SD）を表示。
- **モデル取得**: transformers.js は HF から直接取得 + 独自キャッシュを持つため、
  `SD_CACHE_ENABLED=true` でキャッシュ許可（LLM の「キャッシュなし」方針は画像モデルでは解除。
  理由: モデルが重く、再ダウンロードのコストが生成体験を壊すため。設定で無効化可能にする）。
- **進捗**: ダウンロード進捗（バイト数）と生成進捗（step / total steps）を別々に表示。

## 5. T2I（テキスト → 画像）初期仕様

- モデル（初期候補、サイズは目安・要検証）:
  - **sd-turbo** 系: 1〜4 step で生成できる軽量モデル。モバイル向けの第一候補。
  - **SD 1.5** ONNX fp16: 約 2GB。品質重視のデスクトップ向け第二候補。
  - SDXL 級（約 5GB+）: iPad では現実的に不可。デスクトップのみ許可（要検証）。
- パラメータ: prompt / negative prompt / steps / guidance / seed / width / height。
- 解像度: 既定 512×512。モバイルは 512 固定、失敗時は 384 に階梯フォールバック（LLM の M-4 と同じ発想）。
- seed 固定入力により再現性を確保（UI に前回 seed の自動表示）。

## 6. I2I（画像 → 画像）初期仕様

- 入力画像は canvas で目標解像度にリサイズしてから渡す（EXIF 回転も吸収）。
- **strength**（元画像の再描画度合い 0.0〜1.0）をスライダーで指定。
- 画像入力はドラッグ&ドロップ + クリップボード貼り付けに対応。
- Inpainting（マスク描画 UI）は S4 以降。まずは img2img のみ。

## 7. デバイス制約とフォールバック

| 状況 | 動作 |
| --- | --- |
| WebGPU 不可（Safari 17 以前・ドライバ無効など） | WASM EP は実用速度にならないため「画像生成には WebGPU 対応ブラウザが必要」と案内して遮断（または設定で強制試行） |
| ロード中のメモリ不足 | 解像度階梯（512 → 384 → 320）とモデル階梯（SD1.5 → sd-turbo）を自動試行 |
| iPad / モバイル | モデル 2GB 超は遮断。生成 1 枚ごとに中間テンソルを確実に解放 |
| LLM がロード済み | 画像モデルのロード前に LLM を unload し、確認ダイアログを出す |

## 8. マイルストーン

| 段階 | 内容 | 完了条件 |
| --- | --- | --- |
| **S1** | transformers.js で T2I 最小実装（モデル 1 種・512px・進捗表示・1 枚生成） | デスクトップ Chrome で生成完了 |
| **S2** | I2I + パラメータ UI 完備・モデル切替・キャッシュ管理・ギャラリー | iPad Safari で sd-turbo が動く |
| **S3** | stable-diffusion.cpp(GGUF) WASM の PoC 検証・LLM との排他制御完成 | GGUF 版の速度/メモリ実測レポート |
| **S4** | Inpainting / ControlNet / SD 用 LoRA の検討 | （検討結果で確定） |

## 9. リスクと未確定事項

- ORT-Web の WebGPU EP における fp16 の端末差（要検証。int8 量子化版での代替を想定）。
- iOS Safari の WebGPU は OS / バージョン依存が強く、iPad 実機での検証が必須。
- transformers.js のモデルリポジトリ側の整形（ONNX 変換済みか否か）を事前確認する必要あり。
- sd.cpp WASM は webgpu バックエンドの成熟度が読めないため、S3 は「捨ててもよい PoC」と位置づける。
- 生成モデルのライセンス（CreativeML Open RAIL 系など）をモデルごとに確認し、画面に帰属表示を出す。

### appConfig への追加変数（予定・名称は仮）

```ts
SD_DEFAULT_MODEL_URL: string;      // 既定の画像生成モデル（ONNX リポジトリ ID or URL）
SD_CACHE_ENABLED: boolean;         // モデルキャッシュ（既定 true）
SD_SIZE: 512;                      // 既定解像度
SD_STEPS: 4;                       // 既定 step 数（モデル種別で変わる）
SD_GUIDANCE: number;               // guidance scale
SD_I2I_DEFAULT_STRENGTH: 0.6;      // img2img の既定 strength
SD_AUTO_UNLOAD_LLM: boolean;       // 画像生成前に LLM を自動 unload（既定 true）
```
